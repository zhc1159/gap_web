## 1. 软件概述

### 1.1 系统定位

本软件是 GAP 安全隔离网闸的 Web 管理前端，为网闸设备提供图形化的配置管理、状态监视、策略下发、日志审计等能力。管理员通过浏览器访问本系统，即可完成网闸的日常运维工作，所有业务数据通过 HTTP/HTTPS 与后端服务交互。

### 1.2 技术架构

| 分类 | 技术 | 说明 |
|------|------|------|
| 前端框架 | Vue 3.4 + TypeScript 5.2 | 组合式 API，类型安全 |
| 构建工具 | Vite 5.2 | 开发热更新、生产打包 |
| UI 组件库 | Element Plus 2.7 | 中文组件生态完整 |
| 状态管理 | Pinia 2.1 | 用户/系统全局状态 |
| 路由 | Vue Router 4.3（Hash 模式） | URL 带 `#`，静态部署无需服务端路由兜底 |
| 国际化 | vue-i18n 9 | 内置简体中文 / English，可切换 |
| 图表 | ECharts 5.5 | 流量统计、实时监控可视化 |
| HTTP 请求 | Axios 1.6 | 统一拦截器、Token 注入、错误提示 |

### 1.3 目录结构

## 3. 编译打包

### 3.1 获取源码

```bash
# 内部 GitLab（dev 分支）
git clone git@172.199.199.11:SWGAP_new/new_web.git
cd new_web
git checkout dev

# 或 GitHub 镜像
git clone git@github.com:zhc1159/gap_web.git
```

### 3.2 安装依赖

```bash
npm install
```

### 3.3 开发调试

```bash
# 方式一：直接启动（默认端口 3000）
npm run dev

# 方式二：使用启动脚本（可指定端口，自动清理占用进程）
./start.sh 3001
```

启动后浏览器访问 `http://<开发机IP>:3000/`，修改代码实时热更新。

开发环境下后端地址读取 `public/ipconfig.js`，默认指向 `http://127.0.0.1:3002`，按实际环境修改即可（Vite 会将 `public/` 原样拷贝，改动无需重启）。

### 3.4 生产构建

```bash
npm run build
```

构建流程：先执行 `vue-tsc` 类型检查，再由 Vite 打包。产物输出到 `dist/` 目录：

```
dist/
├── index.html
├── ipconfig.js        # 环境配置（部署时可改）
├── favicon.ico
└── assets/            # 带哈希的 JS / CSS / 图片
```

> 类型检查失败会导致构建中断，请先修复 TS 报错。如仅需跳过检查快速出包，可临时使用 `npx vite build`。

## 4. 部署指南

### 4.1 部署架构

```
浏览器 ──HTTP──▶ Nginx（静态托管 dist/） ──代理/直连──▶ 网闸后端服务(:3002)
                                          └──WebSocket──▶ WS_IP
```

前端为纯静态资源，后端地址通过 `ipconfig.js` 在浏览器端注入，**修改后端地址不需要重新编译，改文件后刷新页面即可生效**。

### 4.2 配置后端地址

编辑 `dist/ipconfig.js`：

```js
window.envs = {
  BASE_API_IP: "http://172.199.199.20:3002",   // 后端 HTTP 服务地址
  WS_IP: "ws://172.199.199.20:3002",           // WebSocket 地址（流量监控等）
  UKEY_IP: "http://172.199.3.101:51235"        // UKey 服务地址（按需）
}
```

### 4.3 Nginx 部署

将 `dist/` 整个目录上传到服务器，例如 `/opt/gap-web/dist`。

`nginx.conf` 参考配置：

```nginx
server {
    listen       80;
    server_name  _;

    root /opt/gap-web/dist;
    index index.html;

    # 静态资源缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # ipconfig.js 不缓存，保证修改立即生效
    location = /ipconfig.js {
        expires -1;
        add_header Cache-Control "no-cache";
    }

    # 前端使用 Hash 路由，无需 try_files 兜底，直接托管即可
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

生效：

```bash
nginx -t          # 检查配置
nginx -s reload   # 重新加载
```

> 如后端开启了跨域支持，浏览器直接访问 `BASE_API_IP` 即可，Nginx 无需代理 API。若需要 Nginx 统一代理（同域部署、避免跨域），可增加：
> ```nginx
> location /api/ {
>     proxy_pass http://172.199.199.20:3002/;
> }
> ```
> 并将 `ipconfig.js` 的 `BASE_API_IP` 改为 `"/api"`。

### 4.4 验证

1. 浏览器访问 `http://<服务器IP>/`，出现登录页即静态部署成功
2. 输入账号密码登录，若能进入主界面且各页面数据正常加载，说明后端地址配置正确
3. 打开「监控 → 流量统计」，图表实时刷新说明 WebSocket（`WS_IP`）连通正常

### 4.5 版本升级

```bash
# 服务器上备份旧版本
cp -r /opt/gap-web/dist /opt/gap-web/dist.bak.$(date +%Y%m%d)

# 上传新 dist/ 覆盖，并按需修改 ipconfig.js
nginx无需重启，刷新浏览器即可（静态资源带哈希，自动加载新版本）
```

## 5. 常见问题

| 现象 | 原因与解决 |
|------|-----------|
| `npm install` 缓慢 | 更换国内源：`npm config set registry https://registry.npmmirror.com` |
| 开发端口被占用 | `./start.sh <端口>` 自动清理，或手动 `kill -9 $(lsof -t -i:3000)` |
| 页能打开但登录/数据报错 | `ipconfig.js` 中 `BASE_API_IP` 配置错误或后端未启动；浏览器 F12 Network 查看请求实际地址 |
| 流量图表不动 | `WS_IP` WebSocket 地址不通，检查防火墙/后端 WS 服务 |
| 修改 ipconfig.js 不生效 | 浏览器缓存，强制刷新（Ctrl+F5）；按 4.3 配置该文件不缓存 |
| 页面空白 + 控制台报资源 404 | 静态资源路径问题，确认访问的是站点根路径，或检查 Nginx root 指向 |
| 构建报 TS 类型错误 | `npm run build` 含 `vue-tsc` 检查，按报错修复；紧急可 `npx vite build` 跳过 |
| 修改代码浏览器无变化 | 清理 Vite 缓存：`rm -rf node_modules/.vite` 后重启开发服务器 |
| 登录后一会就退出 | Token 存于 sessionStorage，关闭浏览器标签即失效，属正常设计 |
